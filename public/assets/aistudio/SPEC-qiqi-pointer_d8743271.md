单行版（放进 `d="..."`）：

```

```

**结构**：4 个顶点、3 段圆弧、4 段直线，共 7 段。**没有一段是贝塞尔曲线。**
这一点很重要——意味着放大到 1024 也不会有曲率抖动。

### 3.2 顶点坐标（全精度）

| 顶点 | 坐标 | 说明 |
|---|---|---|
| V1 | `(27.947712, 20.000000)` | 顶部尖端 |
| V2 | `(25.677343, 72.000000)` | 左下翼端 |
| V3 | `(43.212175, 56.851674)` | 中间凹口（把儿与身体的交界） |
| V4 | `(66.322657, 55.164159)` | 右翼端（把儿的尖） |

顶点顺序沿边界走：**V1 → V2 → V3 → V4 → 闭合回 V1**。

### 3.3 角度

```
张角 = V1 内角                50.0000°  凸     ← 同一件事，不是两个约束
V2 内角                     46.6763°  凸
V3 内角                    143.3526°  凹     ← 注意：凹角，不是凸角
V4 内角                     46.6763°  凸
对称轴方向                   67.5°（自水平，屏幕坐标顺时针为正、y 向下）
左翼方向                    92.5°（= 67.5 + 50/2，比垂直多 2.5°）
右翼方向                    42.5°（= 67.5 − 50/2）
```

> 「张角」和「V1 内角」是同一个角，不要当成两个独立参数去凑。V2 与 V4 的内角必然相等（对称），如果不相等就是抄错了。

**这个形是轴对称的**，对称轴穿过 V1 与 V3。所以左边那条边**不是严格垂直的**——它相对垂直倾斜了 2.5°（左翼方向 92.5°、右翼 42.5°）。这是对称的必然结果：只让右边张开、左边不动，就不可能对称。

验证对称性（两组数必须相等）：

```
|V1→V2| = 52.0495     |V1→V4| = 52.0495     差 0.0000
|V3→V2| = 23.1720     |V3→V4| = 23.1720     差 0.0000
```

复刻时如果这两组数对不上，说明角度抄错了。

### 3.4 圆角（关键：四个角半径不同）

| 顶点 | 半径 | 切点距 | 角型 | 状态 |
|---|---|---|---|---|
| V1 尖端 | **1.00** | 2.1445 | 凸 | 轻圆 |
| V2 左下 | **1.00** | 2.3177 | 凸 | 轻圆 |
| V3 凹口 | **0.00** | 0 | 凹 | **尖角，无圆弧** |
| V4 右下 | **1.00** | 2.3177 | 凸 | 轻圆 |

**V3 是尖角**——路径里 V3 处是 `L43.21 56.85 L64.01 55.33`，两条直线直接相接，没有 `A` 命令。这是刻意的。

**圆角算法**（若要按参数重算，不要手描）：

```
切点距  t = r / tan(θ/2)          θ = 该顶点内角
圆心    在角平分线方向上，距离 r / sin(θ/2)
弧方向  凸角与凹角相反（凹角那条弧朝材料内侧弯）
```

**凹角圆角的视觉深度**（复刻时最容易踩的坑）：

```
D = r × (1 / sin(θ/2) − 1)
```

- V3 是 143.35° 的钝角 → 系数 **0.0538**
- V2 / V4 是 46.68° 的锐角 → 系数 **1.525**

同样半径，凹口的效果只有翼端的 **1/28**。所以历史上一度给凹口 r=1.4，结果完全看不出来（实测弦长甚至比尖角还少）。**现在定稿的凹口是 0，不做圆角，不要"顺手"给它加一个。**

## 5. 待机动效（idle）

四条通道，周期**互不整除**，所以永远不会同时回到起点——这是"不像机器"的全部秘密。

| 通道 | 做法 | 周期 | 幅度 |
|---|---|---|---|
| 眨眼 | 两个孔的 `ry` 压到 **18%** | 3.2s | 2.83→0.509 / 2.23→0.401 |
| 扫视 | 两个孔的 `cx/cy` 分别位移 | 7.6s | 四段停顿，见下 |
| 摆动 | 整支形绕**尖端**旋转 | 5.2s | ±0.55° |
| 呼吸 | 整体缩放，绕**质心** | 5.6s | 1 → 1.025 |

**扫视的四个停位**（相对静止位置的偏移）：

```
位 0  (+0.85, −0.75)
位 1  (−0.95, −0.55)
位 2  (+1.05, +0.45)
位 3  (−0.35, +1.05)
keyTimes  0;0.16;0.18;0.44;0.46;0.68;0.70;0.86;0.88;1
```

每段之间是一次 0.02 周期的插值（约 0.15s），然后停住——形成"看一下、停、再看一下"的节奏。

**两个旋转轴必须分开：**

```
摆动  rotate 轴 = (27.95, 20.00)   尖端，不是体心
呼吸  scale 轴 = (39.05, 46.82)    质心
```

> 同一个 `<g>` 只能挂**一个** `animateTransform`。摆动（rotate）和呼吸（scale）必须分层，否则后挂的会覆盖前一个。

**眨眼的关键**：`ry` 压到 **18%** 才是一条干净的缝。压到 0 会变成 0 高度的线，抗锯齿后是一道虚线。

## 6. 思考动效（think）· 本版重新设计

### 6.1 它做什么

**两只眼睛作为刚体，绕两眼中点这一个圆心连续旋转 360°，3.2 秒一整圈，线性匀速。**

```xml
<g>
  <animateTransform attributeName="transform" type="rotate"
    values="0 41.57 46.00;360 41.57 46.00"
    keyTimes="0;1" dur="3.2s" repeatCount="indefinite" calcMode="linear"/>
  <ellipse cx="36.952" cy="45.600" rx="2.83" ry="2.83" fill="#000"/>
  <ellipse cx="46.182" cy="46.400" rx="2.23" ry="2.23" fill="#000"/>
</g>
```

旋转中心 `(41.57, 46.00)` = 一对眼睛的中心。**不是**各自的圆心，**不是**形状的质心。

### 6.2 为什么必须这样（重要，别自己改）

"两只眼睛绕同一圆心转"在几何上只有**一个**自洽解：两孔必须在**同一个圆**上，也就是以圆心对称分布、刚性旋转。

如果把"整对平移着绕圈"当作实现——两孔各自保持水平、整对沿一个小圆滑动——那么**左眼的轨迹圆心与右眼的轨迹圆心相差 9.23**，那就是两个圆心，不是同一圆心。

所以：**旋转，不是平移。** 转到 90° 时两孔呈上下排列，转到 180° 时左右互换——这是预期行为，不是 bug。

### 6.3 本版删掉了什么

| 项 | 旧版 | 本版 | 原因 |
|---|---|---|---|
| 右眼眯到 78% | 有 | **删除** | 旋转中眯眼会跟着倾斜，读起来像形状错误 |
| 每眼绕自身圆心画小圈 | 有（o = 0.46r） | **删除** | 两个独立圆心，不是"同一圆心" |
| 身体摆动 ±1.7° / 1.9s | 有 | **保留，未改** | 与眼睛旋转是两个独立通道 |
| 呼吸 0.986 / 3.2s | 有 | **保留，未改** | 同上 |

### 6.4 与待机的差异对照

| 通道 | 待机 | 思考 |
|---|---|---|
| 眨眼 | 3.2s | **无**（旋转时眨眼会破坏刚体感） |
| 眼睛运动 | 扫视四段 / 7.6s | **绕共同圆心旋转 / 3.2s** |
| 摆动 | ±0.55° / 5.2s / spline 缓动 | ±1.7° / 1.9s / **linear** |
| 呼吸 | ×1.025 / 5.6s | ×0.986 / 3.2s（收缩，不是放大） |

## 10. 小尺寸注意事项

| 尺寸 | 用哪个 | 理由 |
|---|---|---|
| ≥ 96 | 动效版 | 眨眼、扫视、旋转全部可读 |
| 64 – 96 | 动效版 | 只剩旋转和摆动明显，扫视接近不可见 |
| 44 – 64 | 静态标（可选动效） | 带温度，但看不出在演什么 |
| ≤ 44 | **静态标** | 动起来只会抖。这个尺寸要"一秒认出" |

圆角 r=1.0 在 24px 上只有 0.26px——**小尺寸里它等于不存在**，这正好：大尺寸去掉毛刺感，小尺寸保留锐利。

思考动效在 48px 以下基本读不出"在转"（旋转半径 4.64 缩到 24px 只有 1.2px 位移）。建议动效 ≥64。

## 11. 附：这个形是怎么定下来的（理解用，不要拿去"重新生成"）

如果你想知道为什么是这些数，按时间顺序：

1. 起点是一张 78×63 的灰线截图，要求"改为这样的外轮廓"。
2. 从截图反解：左边一条垂直线、两条 45° 斜边、一条水平把儿，四个圆角分别是 4.26 / 4.63 / 4.11（凹）/ 5.08。
3. 随后发现**这个形原本就是轴对称的**——尖与凹口的连线是轴，两侧翼完全等长（52.00 / 52.06）。这是关键发现。
4. 于是参数化：对称轴方向 67.5°、翼长 52、凹口距尖 39.85，**张角是唯一变量**。
5. 张角从 45° 试到 62°，最终定 **50°**。
6. 圆角从"全尖"试到"凹口 r=10"，最终定 **V1/V2/V4 = 1.0，V3 = 0**。
7. 思考动效从"每眼绕自身圆心转小圈"改为"两孔绕共同圆心刚性旋转"。

**最终参数化的定义（若要重算，从这里出发）：**

```
对称轴方向 A = 67.5°（自水平）
翼长     L = 52
凹口距尖 D = 39.85（沿轴）
张角     APEX = 50°

以尖端为原点（算完再平移缩放到 92 画布，使高度 = 52 且居中）：
  尖   = (0, 0)
  左翼 = L · dir(A + APEX/2)
  右翼 = L · dir(A − APEX/2)
  凹口 = D · dir(A)

然后在四个顶点上加圆角：V1 1.0 / V2 1.0 / V3 0 / V4 1.0
最后缩放到 bbox 高 52、水平居中于 x=46。
```

上面这套参数算出来的原始高度是 51.9505，所以缩放系数 **1.00095**（基本等于不缩放），再平移居中，才得到 §3.2 的四个顶点坐标。**如果你算出来的顶点和 §3.2 差超过 0.01，说明中间某一步用了不同的约定（多半是屏幕坐标 y 向下的方向反了）。**
